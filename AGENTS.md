## Project Overview

catet is a self-hosted, WhatsApp-first personal finance tracker for a small invited set of users, solving visibility first (safe-to-spend clarity), then budgeting, goals, and scattered BNPL/paylater debt.

This repo is the **web dashboard** (Next.js App Router). The **backend** lives in a separate repo:

```
catet-backend/   Go API + domain + docs (source of truth)
catet/           Next.js dashboard (this repo — consumes the backend)
```

---

## Two-Repo Relationship

- **Current repo path:** `/home/glenn/projects/catet` is the UI/dashboard frontend repo.
- **Backend repo path:** `/home/glenn/projects/catet-backend` is the Go backend/API repo and domain source of truth.
- **Backend (`catet-backend`) is the SOURCE OF TRUTH** for the domain model, the ledger engine, the AI harness, and all documentation:
  - `~/projects/catet-backend/CONTEXT.md` — canonical vocabulary (Source, Leg, Transfer, Draft, Safe-to-Spend, …). Read this before naming anything.
  - `~/projects/catet-backend/docs/spec.md` — product & technical spec v2 (plan of record).
  - `~/projects/catet-backend/docs/adr/` — architecture decision records.
  - `~/projects/catet-backend/api/openapi.yaml` — the API contract (to be generated from Go).
- **This repo (`catet`) CONSUMES the backend** — it never owns domain truth.
- The browser talks **only** to Next.js Route Handlers (BFF pattern); the Go API is **internal-only** (docker network, no CORS, no public DNS).
- The frontend uses a **generated, typed API client** from the backend's `openapi.yaml` — contract changes are a PR in the backend, then a regenerate here. No hand-written API types.
- Dashboard manual entry is a **peer capture surface** (`origin=dashboard_manual`, `category_source=user`, no AI gate) — it writes through the same ledger engine as the WhatsApp bot.

## Design Authority (read before any UI work)

The hierarchy of visual truth, in order:

1. **`DESIGN.md` tokens & laws** — colors (cream/ink + semantic `-text` variants), Inter + tabular figures, tight geometry, density rules, naming law. These are binding.
2. **shadcn/ui conventions + good UX judgment** — where shadcn's battle-tested patterns or plain better UX conflict with anything below this line, **prefer them**. Deviating from the mockups is expected and allowed.
3. **Stitch mockups** (`design/` HTML exports) — **reference only**. They were generated by an AI image-model to explore layout, density, and data-flow direction. They are NOT pixel truth, NOT a visual spec, and must NOT be traced literally. Expect and embrace divergence: use shadcn primitives, adjust spacing/arrangement/component choices for a better product.

In short: build from `DESIGN.md` tokens on top of shadcn/Tremor; consult the Stitch screens the way you'd consult a whiteboard sketch — for intent, never for implementation.
